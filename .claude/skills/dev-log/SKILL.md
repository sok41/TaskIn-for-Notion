# 開発ログ記録スキル

## いつ使うか

- ユーザーがGitHubへのpush作業を行った後、「開発ログを記録して」のように**手動で**依頼したときに実行する。
- push操作自体をトリガーにした自動実行（GitHub Actions等）は当面採用しない。このスキル自体も、頼まれていないのに勝手に実行しない。

## 手順

1. **対応内容の把握**
   直近の作業内容を把握する（`git log -1` や `git diff HEAD~1`、このセッションでの会話内容など）。まだpushしていない変更しか無い場合は、pushが完了しているかユーザーに確認する。

2. **要約文の作成**
   コミットメッセージをそのまま転記するのではなく、「何を実装・修正したか」「なぜ」「どう変わったか」を短くまとめた文章を作成する。開発ログを後から読む人（自分自身）が経緯を追えることを目的とする。

3. **Notionへの子ページ追加**
   - 親ページ（開発ログ用ページ）: https://app.notion.com/p/sok4/Dev_TaskIn-3d711b69067880e2a30fd2ad7d0ba626
   - このページの**配下に新規の子ページを1件作成**する（既存ページへの追記ではない。対応内容ごとに新しいページを作る）。
   - Notion MCP（`notion-create-pages` 等）が利用できる場合はそれを使う。使えない場合はユーザーにその旨を伝える。
   - 子ページのタイトルは「日付 + 対応内容の要約」とする（例: `2026-09-10 設定画面にNotion接続テスト機能を追加`）。
   - 本文には手順2で作成した要約文を記載する。

4. **完了報告**
   作成した子ページのURLをユーザーに共有する。

## 注意

- 個人開発ログであり、社外秘情報を含む可能性があるため、内容をNotion以外の場所（Slack等）に転記・共有しない。
- 1回の依頼につき子ページは1件のみ作成する（複数の対応をまとめて依頼された場合はその旨を確認する）。
